# اپلیکیشن اندروید کارگزار

اپلیکیشن مشتری کارگزار با Flutter ساخته شده است.

## وضعیت پیاده‌سازی

- نقطه ورود واقعی برنامه `lib/main.dart` است و در وضعیت فعلی هنوز پوسته قدیمی رابط کاربری را اجرا می‌کند. گردش کار جدید ورود، نشست مشتری و ثبت/پیگیری درخواست در `lib/app/kargozar_app.dart` پیاده‌سازی شده، اما هنوز با رابط کاربری تأییدشده ادغام و از نقطه ورود اجرا نشده است؛ جزئیات در `../docs/mobile-entrypoint-integration-audit-2026-11-18.md` ثبت شده است.
- پوسته برنامه چهار بخش خانه، خدمات، درخواست‌ها و حساب کاربری دارد.
- صفحه خانه و صفحه خدمات، فهرست خدمات را از API دریافت می‌کنند.
- دسته‌بندی‌ها از API خوانده و در کلاینت به ساختار درختی چندسطحی تبدیل می‌شوند؛ انتخاب دسته اصلی، خدمات دسته‌های زیرمجموعه فعال را نیز نمایش می‌دهد.
- جست‌وجوی خدمات، جزئیات پایه خدمات، ایجاد درخواست با کلید idempotency و نمایش کد پیگیری از طریق مخزن‌های API پیاده‌سازی شده‌اند.
- ورود مشتری از مسیر OTP و بازیابی نشست با ذخیره امن توکن پیاده‌سازی شده است.
- صفحه درخواست‌ها، فهرست و رویدادهای وضعیت درخواست‌های مشتری را از API می‌خواند.

## محدودیت‌های محیط عملیاتی

- مقدار عملیاتی `API_BASE_URL` هنوز تنظیم نشده است؛ بنابراین اپلیکیشن عمداً به سرور ساختگی یا HTTP عمومی وصل نمی‌شود.
- ارسال OTP تا انتخاب و تنظیم ارائه‌دهنده پیامک در بک‌اند غیرفعال است.
- برای استفاده واقعی، بک‌اند باید روی دامنه HTTPS معتبر مستقر شود و endpointهای عمومی و احراز هویت آزمایش شوند.
- پرداخت، بارگذاری مدارک و امضای الکترونیک هنوز در این نسخه عملیاتی نشده‌اند.
- APK ساخته‌شده در CI تا پیش از اتصال به API واقعی، نسخه آزمایشی رابط و گردش کار است؛ نه نسخه آماده ارائه به مشتری.

## پیکربندی API

نشانی ریشه API باید شامل پیشوند نسخه باشد:

```bash
flutter run --dart-define=API_BASE_URL=https://api.example.com/api/v1
```

برای ساخت APK آزمایشی:

```bash
flutter build apk --debug
```

در GitHub Actions، متغیر Repository با نام `KARGOZAR_API_BASE_URL` به‌صورت build-time به اپ تزریق می‌شود. جزئیات و شرایط لازم پیش از تنظیم آن در [API_CONFIGURATION.md](API_CONFIGURATION.md) آمده است.

گردش کار GitHub Actions در `../.github/workflows/android-build.yml` فایل‌های Android را تولید، وابستگی‌ها را نصب، کد را تحلیل، تست‌ها را اجرا و APK آزمایشی را می‌سازد. خروجی موفق با نام `kargozar-android-debug` به‌صورت Artifact منتشر می‌شود.
