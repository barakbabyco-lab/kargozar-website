# اپلیکیشن اندروید کارگزار

اپلیکیشن مشتری کارگزار با Flutter ساخته شده است.

## وضعیت پیاده‌سازی

- نقطه ورود واقعی برنامه `lib/main.dart` است و ساختار ناوبری مصوب چهار تب «حساب کاربری من»، «خدمات»، «همراه کسب‌وکار» و «تماس و پشتیبانی» را نمایش می‌دهد.
- تاریخچه درخواست‌ها از داخل حساب کاربری قابل دسترسی است و پیش از نمایش، ورود OTP لازم دارد.
- پنج بنر صفحه خدمات، ده تصویر دسته‌بندی و نه تصویر ماژول همراه کسب‌وکار با نام فایل‌های نهایی و مقصدهای مشخص در `features/content/app_content.dart` تعریف شده‌اند.
- ورود از طریق OTP انجام می‌شود. اگر API تنظیم نشده باشد یا ارسال OTP در بک‌اند غیرفعال باشد، پیام خطای واقعی نمایش داده می‌شود و ورود موفقیت‌آمیزِ ساختگی نداریم.
- کاتالوگ و دسته‌بندی‌های خدمات از API دریافت می‌شوند؛ ساختار دسته‌بندی چندسطحی، جست‌وجو و جزئیات پایه خدمت حفظ شده‌اند.
- فرم ثبت درخواست به نشست احراز هویت‌شده متصل است. ارسال درخواست با شناسه یکتای idempotency انجام می‌شود و پس از پاسخ موفق سرور، کد پیگیری نمایش داده می‌شود.
- صفحه درخواست‌ها، فهرست درخواست‌های مشتری و رویدادهای وضعیت را از API می‌خواند.
- در صورت نبود API، خدمات نمونه صرفاً برای نمایش رابط باقی می‌مانند و امکان ثبت واقعی آن‌ها مسدود است.

## محدودیت‌های محیط عملیاتی و انتشار

- مقدار عملیاتی `API_BASE_URL` و `KARGOZAR_ASSETS_BASE_URL` باید به نشانی‌های HTTPS واقعی تنظیم شوند؛ اپلیکیشن به API یا تصاویر از طریق HTTP ناامن وصل نمی‌شود.
- ارسال OTP در بک‌اند تا زمان تکمیل اتصال ارائه‌دهنده پیامک، تأیید پترن و تست انتهابه‌انتها غیرفعال می‌ماند.
- خرید پنل کاپنل انجام شده است؛ تنظیمات آن فعلاً به درخواست کاربر متوقف است و باید پس از مراجعه مجدد و بررسی پاسخ پشتیبانی ادامه یابد.
- برای استفاده واقعی، بک‌اند باید روی دامنه HTTPS معتبر مستقر شود و endpointهای عمومی، احراز هویت و ثبت درخواست آزمایش شوند.
- پرداخت، بارگذاری مدارک و امضای الکترونیک هنوز در این نسخه عملیاتی نشده‌اند. فرم واقعی مشاوره رایگان و صفحات اجرایی ماژول‌های همراه کسب‌وکار نیز به API و فرایندهای عملیاتی نیاز دارند.
- APK ساخته‌شده در CI تا پیش از اتصال به API واقعی، فعال‌شدن OTP واقعی و تست روی گوشی فیزیکی، نسخه آزمایشی است و نباید به مشتری ارائه شود.

## پیکربندی API

نشانی ریشه API باید شامل پیشوند نسخه باشد:

```bash
flutter run --dart-define=API_BASE_URL=https://api.example.com/api/v1
```

برای ساخت APK آزمایشی:

```bash
flutter build apk --debug
```

در GitHub Actions، متغیرهای Repository با نام‌های `KARGOZAR_API_BASE_URL` و `KARGOZAR_ASSETS_BASE_URL` به‌صورت build-time به اپ تزریق می‌شوند. جزئیات و شرایط لازم پیش از تنظیم آن در [API_CONFIGURATION.md](API_CONFIGURATION.md) آمده است.

## ساخت خودکار

گردش کار GitHub Actions در `../.github/workflows/android-build.yml` فایل‌های Android را تولید، وابستگی‌ها را نصب، کد را تحلیل، تست‌ها را اجرا و APK آزمایشی را می‌سازد. خروجی موفق با نام `kargozar-android-debug` به‌صورت Artifact منتشر می‌شود.
