# اپلیکیشن اندروید کارگزار

اپلیکیشن مشتری کارگزار با Flutter ساخته شده است. نسخه اول برای معرفی خدمات و هدایت کاربر به ارتباط مستقیم با کارشناسان آماده می‌شود.

## امکانات نسخه اول

- نمایش چهار بخش اصلی: «حساب کاربری من»، «خدمات»، «همراه کسب‌وکار» و «تماس و پشتیبانی».
- نمایش ۱۰ دسته اصلی خدمات و ۷۴ زیرشاخه نهایی، همراه با صفحه معرفی مستقل هر خدمت.
- نمایش ۹ ماژول «همراه کسب‌وکار» با صفحه معرفی مستقل.
- تماس مستقیم از صفحات خدمت و مسیرهای ارتباطی با شماره ۰۹۳۶۵۹۵۲۸۰۰.
- نمایش صفحات «درباره کارگزار»، «قوانین و شرایط استفاده» و «سیاست حفظ حریم خصوصی».
- مشاهده محتوای عمومی بدون ساخت حساب، ورود پیامکی یا ثبت‌نام.

## قابلیت‌هایی که عمداً در نسخه اول فعال نیستند

- حساب کاربری مشتری، ورود و ثبت‌نام OTP
- ثبت سفارش و پیگیری درخواست به‌صورت آنلاین
- گفت‌وگوی پشتیبانی و تیکت درون‌برنامه‌ای
- بارگذاری مدارک، پرداخت آنلاین و امضای الکترونیکی

این موارد به نسخه‌های بعد موکول شده‌اند. احراز هویت کارکنان و مدیران در بک‌اند مستقل باقی مانده است.

## شماره تماس ثابت

تمام دکمه‌های تماس مشتری باید به شماره **۰۹۳۶۵۹۵۲۸۰۰** هدایت شوند. تغییر این شماره بدون دستور صریح کاربر مجاز نیست.

## نسخه و شناسه اندروید

- نام برنامه: کارگزار
- شناسه بسته: `ir.kargozar.kargozar_mobile`
- نسخه آماده‌سازی‌شده برای اولین انتشار: `1.0.0+1`

برای به‌روزرسانی نصب موجود، شناسه بسته و کلید امضای انتشار باید ثابت بمانند و فقط شماره نسخه/کد نسخه افزایش یابد.

## وضعیت انتشار در مارکت

اسناد محتوایی در مخزن:
- سیاست حفظ حریم خصوصی: [privacy-policy-fa.html](../docs/privacy-policy-fa.html)
- قوانین و شرایط استفاده: [terms-of-use-fa.html](../docs/terms-of-use-fa.html)
- درباره کارگزار: [about-kargozar-fa.html](../docs/about-kargozar-fa.html)
- متن و چک‌لیست ثبت در مارکت: [marketplace-submission-fa.md](../docs/marketplace-submission-fa.md)

پیش از ثبت نهایی در مارکت باید:
1. صفحات HTML روی دامنه رسمی منتشر و URL عمومی سیاست حفظ حریم خصوصی ثبت شود.
2. آیکون نهایی برند و اسکرین‌شات‌های واقعی نسخه نهایی آماده شوند.
3. کلید امضای Release ایجاد/تأیید و به‌صورت امن در CI تنظیم شود.
4. نسخه Release امضاشده روی گوشی واقعی نصب و آزمایش شود.
5. اطلاعات ناشر، راه ارتباطی، رده سنی و پرسش‌نامه محتوایی مارکت تکمیل شود.

## ساخت و بررسی

گردش کار GitHub Actions در `.github/workflows/android-build.yml` وابستگی‌ها را نصب، کد را تحلیل، تست‌های Flutter را اجرا و APK آزمایشی می‌سازد. اگر کلید امضای انتشار در Secretهای مخزن تنظیم شده باشد، همان گردش کار APK و AAB امضاشده Release را نیز تولید و اعتبارسنجی می‌کند.

برای ساخت محلی APK آزمایشی:

```bash
cd mobile
flutter pub get
flutter analyze lib
flutter test
flutter build apk --debug
```

برای انتشار در مارکت، APK آزمایشی یا Debug قابل استفاده نیست؛ باید AAB یا APK نسخه Release امضاشده با کلید انتشار ثابت ارائه شود.
