# اتصال امن SearXNG به بک‌اند کارگزار روی cPanel

## وضعیت فعلی

- SearXNG روی VPS کارگزار با IP فعلی `194.5.205.233` نصب است.
- سرویس داخلی فقط روی `127.0.0.1:8888` گوش می‌دهد و از اینترنت عمومی قابل دسترسی نیست.
- بک‌اند Laravel روی همان VPS در محیط Staging به سرویس محلی متصل شده و تست زنده دریافت ۵ منبع HTTPS موفق بوده است.
- آدرس `127.0.0.1:8888` فقط برای Laravel هم‌میزبان روی VPS معتبر است؛ استفاده از آن در cPanel اشتباه است، چون loopback هاست cPanel به خود هاست اشاره می‌کند.
- کد Laravel اکنون از endpoint راه‌دور فقط با HTTPS و Bearer Token پشتیبانی می‌کند. اگر endpoint راه‌دور باشد و token تنظیم نشده باشد، درخواست قبل از ارسال رد می‌شود.

## معماری مقصد

```text
Laravel روی cPanel
    |
    | HTTPS GET /search + Authorization: Bearer <secret>
    v
search.<DOMAIN> روی VPS:443
    |
    | reverse proxy داخلی
    v
127.0.0.1:8888 (SearXNG)
```

پورت 8888 هرگز نباید در فایروال عمومی باز شود. فقط reverse proxy روی HTTPS عمومی می‌شود و فقط مسیر `/search` را با توکن معتبر به SearXNG داخلی می‌فرستد.

## پیش‌نیازهای لازم برای فعال‌سازی

1. تعیین دامنه‌ای که مالکیت و کنترل DNS آن تأیید شده باشد؛ پیشنهاد فنی: یک زیردامنه مستقل مانند `search.<DOMAIN>`.
2. ثبت رکورد DNS نوع A برای زیردامنه به IP فعلی VPS: `194.5.205.233`.
3. تأیید اینکه پورت‌های عمومی TCP 80 و 443 روی VPS آزادند یا reverse proxy فعلی قابلیت افزودن virtual host دارد. قبل از این بررسی، سرویس وب فعلی نباید متوقف یا جایگزین شود.
4. صدور گواهی TLS معتبر برای زیردامنه (برای نمونه با ACME/Let's Encrypt).
5. تولید یک Bearer Token تصادفی و بلند (حداقل 32 بایت تصادفی). این مقدار باید فقط در فایل محیطی امن reverse proxy روی VPS و متغیر محیطی `SEARXNG_API_TOKEN` روی cPanel ذخیره شود؛ نه در Git، چت، فایل عمومی یا مرورگر.
6. تنظیم `SEARXNG_URL=https://search.<DOMAIN>/search` و `SEARXNG_API_TOKEN=<secret>` در فایل `.env` خصوصی بک‌اند cPanel.
7. اجرای تست end-to-end از محیط PHP روی cPanel؛ سپس بررسی اینکه درخواست بدون توکن یا با توکن اشتباه پاسخ 401 می‌گیرد و درخواست معتبر JSON دریافت می‌کند.

## کنترل‌های امنیتی الزامی

- TLS معتبر و اعتبارسنجی گواهی در Laravel روشن بماند؛ هیچ گزینه‌ای برای غیرفعال‌کردن TLS verification اضافه نشود.
- درخواست فقط GET و فقط مسیر دقیق `/search` باشد؛ سایر مسیرها 404 بدهند.
- درخواست بدون Bearer Token معتبر 401 بگیرد.
- لاگ reverse proxy نباید مقدار Authorization را ثبت کند.
- توکن در پاسخ‌ها، پیام خطا یا logهای Laravel نمایش داده نشود.
- SearXNG همچنان فقط روی loopback بماند.
- جست‌وجو فقط برای پرسش‌های عمومی و غیرحساس انجام شود؛ پالایش شماره تلفن و ایمیل در Laravel حفظ شود.
- دسترسی عمومی به endpoint جست‌وجو باید با rate limit در reverse proxy یا لایه جلویی محدود شود.
- قبل از تغییر پورت‌های 80/443، سرویس‌های موجود VPS شناسایی شوند تا استقرار Staging یا وب‌سایت دیگری قطع نشود.

## تنظیمات Laravel

در `backend/config/support_assistant.php`:
- `endpoint` از `SEARXNG_URL` خوانده می‌شود.
- `token` از `SEARXNG_API_TOKEN` خوانده می‌شود.
- endpoint راه‌دور فقط وقتی پذیرفته می‌شود که scheme برابر HTTPS و token غیرخالی باشد.
- endpoint محلی `http://127.0.0.1:8888/search` برای استقرار هم‌میزبان بدون token مجاز است.

نمونه تنظیم cPanel (فقط پس از نصب gateway و ذخیره توکن واقعی روی سرور):
```dotenv
SUPPORT_WEB_SEARCH_ENABLED=true
SEARXNG_URL=https://search.<DOMAIN>/search
SEARXNG_API_TOKEN=<secret>
```

## وضعیت نهایی و مانع باقی‌مانده

اتصال VPS/Staging کامل و تست شده است. کد پشتیبانی endpoint راه‌دورِ دارای Bearer Token اضافه شده است؛ تست‌های بک‌اند و مهاجرت MySQL 8 در CI موفق‌اند و نسخه Staging با همین کد مستقر شده است. تست زنده روی VPS همچنان ۵ منبع HTTPS برمی‌گرداند.

اتصال cPanel را عمداً فعال نمی‌کنیم تا دامنه مقصد، کنترل DNS، گواهی TLS و وضعیت پورت‌های 80/443 سرور مشخص شوند. بازکردن مستقیم پورت 8888 یا استفاده از HTTP عمومی، جایگزین قابل قبول نیست. هیچ دامنه‌ای را بدون تأیید مالکیت و کنترل کاربر حدس نمی‌زنیم.
