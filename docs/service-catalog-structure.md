# ساختار مرجع دسته‌بندی خدمات کارگزار

وضعیت: فهرست دسته‌های اصلی و زیرشاخه‌های زیر بر اساس تصمیم‌های تأییدشده کاربر ثبت شده است.
تاریخ ثبت: 2026-11-18

## اصل ساختار

- کاتالوگ باید چندسطحی باشد: دسته اصلی، زیرشاخه و در صورت نیاز سطح جزئی‌تر.
- مشتری خدمات را مستقل انتخاب می‌کند؛ بسته اجباری وجود ندارد.
- قیمت و زمان انجام می‌توانند برای هر خدمت جداگانه تعریف شوند و تا زمان بررسی پرونده قطعی نیستند.
- ترتیب نمایش دسته‌ها باید مطابق شماره‌های زیر باشد.
- این سند مرجع محتوایی کاتالوگ است؛ هنوز به معنی ورود همه موارد به دیتابیس عملیاتی نیست.

## وضعیت فنی پیاده‌سازی

مدل دسته‌بندی چندسطحی در بک‌اند پیاده‌سازی شده است:
- ستون nullable به نام `parent_id` با self-reference و محدودیت حذف والد دارای فرزند اضافه شده است.
- مدل Eloquent رابطه‌های `parent` و `children` دارد و ساختار چندسطحی را بدون محدودیت عمق کاربردی پشتیبانی می‌کند.
- API عمومی فهرست دسته‌ها را با `parent_id` و `has_children` برمی‌گرداند.
- فیلتر خدمات با انتخاب یک دسته، خدمات تمام زیرشاخه‌های فعال آن را نیز شامل می‌شود.
- غیرفعال‌شدن هر والد، تمام شاخه زیرمجموعه آن را از کاتالوگ عمومی پنهان می‌کند؛ داده‌ها حذف نمی‌شوند.
- پنل کارکنان امکان ساخت و جابه‌جایی دسته‌ها را با کنترل چرخه‌های والد/فرزند دارد.
- Seeder کاتالوگ به ۱۰ دسته اصلی و زیرشاخه‌های مصوب به‌روزرسانی شده و خدمات نمونه قبلی را با حفظ شناسه و slug به دسته مناسب منتقل می‌کند. اجرای مجدد Seeder باید idempotent باشد و رکورد تکراری نسازد.
- اپ Flutter در صفحه خدمات، در صورت تنظیم API امن، دسته‌های چندسطحی و خدمات زنده را نمایش می‌دهد؛ رابط تأییدشده حفظ شده است.

این تغییرات در مخزن توسعه ثبت شده‌اند؛ بااین‌حال اجرای Seeder یا migration روی محیط عملیاتی تا زمان آماده‌شدن محیط استقرار، بررسی داده‌های واقعی و تأیید نسخه پشتیبان ممنوع است.
