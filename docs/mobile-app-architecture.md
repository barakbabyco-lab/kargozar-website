# معماری فنی اپلیکیشن کارگزار

## تصمیم نسخه اول
- اپلیکیشن مشتری: Flutter
- بک‌اند و API: Laravel روی میزبانی لینوکسی سازگار با PHP 8.3
- پایگاه داده: MySQL
- پنل کارشناسان و مدیریت: وب‌اپلیکیشن متصل به همان API
- وب‌سایت معرفی خدمات: مستقل از اپلیکیشن، با امکان اتصال به API

## اصل مهم
اپلیکیشن، وب‌سایت و پنل مدیریت مستقیماً به دیتابیس وصل نمی‌شوند. تمام ارتباط‌ها از API احراز هویت‌شده عبور می‌کنند. اطلاعات مشتریان و پرونده‌ها در دیتابیس مستقل کارگزار نگهداری می‌شود و با داده‌های باراک مد مخلوط نخواهد شد.

## محیط‌ها
- توسعه: داده ساختگی، بدون مدارک واقعی مشتری
- آزمایشی: دامنه موقت و دیتابیس جدا
- عملیاتی: دامنه نهایی، SSL، پشتیبان‌گیری و دسترسی محدود

## اجزای نسخه MVP
1. فهرست دسته‌بندی‌ها و خدمات
2. ثبت‌نام/ورود با شماره موبایل و کد یک‌بارمصرف پس از انتخاب سرویس پیامکی
3. ثبت درخواست خدمت
4. بارگذاری امن مدارک پس از راه‌اندازی ذخیره‌سازی امن
5. کد پیگیری و تاریخچه وضعیت درخواست
6. پنل کارشناسان برای مشاهده، ارجاع و به‌روزرسانی پرونده‌ها

## ملاحظات امنیتی
- رمز عبور و توکن‌ها هرگز در کد اپلیکیشن ثابت قرار نمی‌گیرند.
- فایل‌های هویتی در مسیر عمومی وب قرار نمی‌گیرند.
- دسترسی کاربر به پرونده‌ها فقط بر اساس مالکیت و نقش کنترل می‌شود.
- تمام درخواست‌های مدیریتی ثبت رویداد می‌شوند.
- نسخه پشتیبان دیتابیس و فایل‌ها باید جداگانه و منظم تهیه شود.
- پرداخت و امضای الکترونیکی تا زمان انتخاب ارائه‌دهنده و بررسی الزامات حقوقی، فعال نمی‌شوند.

## محدودیت میزبانی فعلی
هاست فعلی باراک مد حدود ۱.۳ گیگابایت فضای آزاد گزارش شده و نسخه PHP فعلی 8.1 است؛ امکان انتخاب نسخه‌های دیگر نیز اعلام شده است. پیش از استقرار Laravel باید نسخه PHP سازگار (ترجیحاً 8.3)، Composer/SSH یا روش نصب وابستگی‌ها، افزونه‌های PHP، محدودیت پردازش، فضای فایل و امکان ساخت دیتابیس مستقل تأیید شود. در صورت ناکافی بودن منابع، محیط آزمایشی روی سرویس جدا می‌ماند و درباره سرور عملیاتی بعداً تصمیم می‌گیریم.
