# گزارش ممیزی DNS دامنه kargozarr.ir
تاریخ بررسی: 2026-11-18

## خلاصه وضعیت
- دامنه در WHOIS رسمی ایرنیک ثبت‌شده است.
- نیم‌سرورهای ثبت‌شده در WHOIS:
  - `ns929.mihanwebhost.com`
  - `ns930.mihanwebhost.com`
- با وجود ثبت دامنه و وجود zone فعال روی نیم‌سرورهای MihanWebHost، هر چهار سرور authoritative پسوند `.ir` در زمان بررسی برای `kargozarr.ir` پاسخ `NXDOMAIN` برگرداندند. این ناهماهنگی باید پیش از تغییر نهایی delegation با ایرنیک بررسی شود.
- روی VPS با IP `194.5.205.233`، سرویس BIND 9.18.39 فعال است؛ اما zone اختصاصی `kargozarr.ir` هنوز تعریف نشده است.
- هیچ تغییری در DNS عمومی، نیم‌سرورهای ایرنیک یا تنظیمات BIND اعمال نشده است. تمام بررسی‌های انجام‌شده read-only بوده‌اند.

- نیم‌سرورها:
  - `ns930.mihanwebhost.com`
  - `ns929.mihanwebhost.com`

## نتایج zone فعلی روی MihanWebHost
هر دو نیم‌سرور MihanWebHost برای zone پاسخ authoritative داده‌اند و SOA یکسان با serial برابر `2026111700` برگردانده‌اند.

رکوردهای مشاهده‌شده:
| نام / نوع | مقدار |
|---|---|
| `kargozarr.ir A` | `89.32.248.121` |
| `www.kargozarr.ir CNAME` | `kargozarr.ir` |
| `kargozarr.ir MX` | `0 mail.kargozarr.ir` |
| `mail.kargozarr.ir A` | `89.32.248.121` |
| `kargozarr.ir TXT` | `v=spf1 +a +mx +ip4:89.32.248.121 ~all` |
| `webmail.kargozarr.ir A` | `89.32.248.121` |
| `ftp.kargozarr.ir A` | `89.32.248.121` |

- برای apex رکورد AAAA و CAA مشاهده نشد.
- برای `smtp`، `imap`، `pop` و `autodiscover` رکورد A مشاهده نشد.
- درخواست AXFR از MihanWebHost رد شد.
- پاسخ HTTP و HTTPS به IP قدیمی `89.32.248.121` با Host دامنه، در زمان بررسی `500 Internal Server Error` بود.

**نکته مهاجرت:** اگر DNS به VPS منتقل شود، رکوردهای ایمیل نباید ناخواسته حذف شوند. تا زمان انتقال مستقل سرویس ایمیل، MX و رکوردهای `mail`، `webmail`، `ftp` و SPF باید با دقت حفظ شوند. رکورد A اصلی وب‌سایت پس از آماده‌شدن وب‌سرور می‌تواند به `194.5.205.233` تغییر کند.

## وضعیت VPS و BIND
- سیستم‌عامل: Ubuntu 24.04.5 LTS
- BIND: نسخه 9.18.39، سرویس active و enabled
- فضای دیسک: 58 GB کل، حدود 54 GB آزاد
- حافظه قابل استفاده: حدود 2.9 GiB
- پورت 53 روی آدرس‌های عمومی سرور listen است.
- تنظیمات فعلی BIND:
  - `recursion no;`
  - `allow-query { any; };`
  - `allow-transfer { none; };`
  - `listen-on` شامل loopback و IP عمومی VPS
  - `listen-on-v6 { none; };`
- فایل `named.conf.local` هنوز zone اختصاصی ندارد.
- `named-checkconf -z` برای zoneهای پیش‌فرض بدون خطا اجرا شد.
- تست query به IP عمومی VPS از خود VPS پاسخ DNS با وضعیت REFUSED داد؛ این پاسخ نشان می‌دهد daemon روی IP پاسخ می‌دهد، اما zone موردنظر هنوز تعریف نشده است. دسترسی واقعی از اینترنت بیرونی باید جداگانه تست شود.

## محدودیت دسترسی اجرایی
- کلید SSH موجود در GitHub به حساب عادی deployment وصل می‌شود.
- حساب deployment شناسه UID برابر 1000 دارد و عضو گروه `www-data` است؛ عضو گروه `sudo` نیست.
- اجرای `sudo -n` با درخواست رمز متوقف می‌شود.
- ورود SSH به حساب root با همین کلید مجاز نیست.
- بنابراین تا زمانی که دسترسی مدیریتی محدود و امن فراهم نشود، امکان نوشتن فایل‌های BIND یا reload کردن سرویس از مسیر فعلی وجود ندارد.
- رمز root، رمز sudo یا کلید خصوصی SSH نباید در چت یا مخزن GitHub قرار گیرد.

## تصمیم‌های فنی لازم پیش از اعمال تغییر
1. ابتدا باید ناهماهنگی بین WHOIS ایرنیک و zone منتشرشده در `.ir` روشن شود.
2. چون فعلاً فقط یک IP عمومی VPS موجود است، نباید دو nameserver مستقل را صرفاً با دو نام روی همان IP معرفی کنیم. معیارهای فنی IANA حداقل دو nameserver با IPهای متفاوت و تنوع شبکه را توصیه/الزام می‌کنند: https://www.iana.org/help/nameserver-requirements
3. گزینه‌های معماری:
   - حفظ nameserverهای MihanWebHost و تغییر رکورد A وب به VPS؛ ساده‌تر، ولی BIND روی VPS authoritative نخواهد بود.
   - BIND روی VPS به‌عنوان primary و یک DNS secondary مستقل در شبکه/IP دیگر؛ مناسب‌تر برای استفاده از BIND و افزونگی، ولی نیازمند پیکربندی امن AXFR/TSIG و ثبت delegation و glue در ایرنیک است.
4. پس از تعیین معماری و فراهم‌شدن دسترسی محدود مدیریتی، zone با حفظ رکوردهای ایمیل ساخته، اعتبارسنجی و reload می‌شود.
5. در پایان، پاسخ authoritative روی UDP و TCP پورت 53 از خارج VPS، delegation ایرنیک، رکوردهای وب و ایمیل و سازگاری NSها بررسی می‌شوند.

## پیشنهاد تکمیلی برای معماری با یک IP
با توجه به اینکه فعلاً فقط یک IP عمومی در اختیار داریم، پیشنهاد فنی کم‌ریسک این است:
- BIND روی VPS به‌عنوان Primary/Hidden Master باقی بماند.
- یک سرویس مستقل به‌عنوان Secondary عمومی، zone را با AXFR/IXFR و TSIG دریافت کند.
- نیم‌سرورهای عمومی ثبت‌شده در ایرنیک از سرویس ثانویه باشند؛ BIND روی VPS منبع اصلی داده باقی بماند.

گزینه بررسی‌شده: ClouDNS
- مستندات ClouDNS پشتیبانی از Secondary DNS و انتقال zone از Master را توضیح می‌دهد.
- پلن Premium S از 2.95 دلار در ماه شروع می‌شود و صفحه رسمی، دوره آزمایشی 30 روزه را اعلام می‌کند.
- پیش از فعال‌سازی باید جزئیات فعلی پلن، نام NSهای تخصیص‌یافته، IPهای AXFR و شرایط پرداخت از داخل حساب تأیید شود.
- مستندات: https://www.cloudns.net/secondary-dns/ و https://www.cloudns.net/wiki/article/673/

این گزینه هنوز فعال نشده و نیازمند تأیید هزینه/استفاده از سرویس خارجی است.

- رکوردهای MX، mail، webmail، SPF و سایر رکوردهای مرتبط با ایمیل و سرویس‌های موجود در MihanWebHost باید حفظ شوند.
- پیش از تغییر رکورد A، باید وب‌سرور، TLS/SSL، فایروال و تست دسترسی مستقیم به IP آماده باشند؛ سپس تغییر DNS با امکان بازگشت انجام شود.
