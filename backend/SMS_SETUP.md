# راه‌اندازی پیامک ورود یک‌بارمصرف کارگزار

## وضعیت پیاده‌سازی

ارسال OTP در بک‌اند Laravel از قبل به ارائه‌دهنده IPPanel Edge متصل شده است. اگر هر سه تنظیم زیر خالی باشند، برنامه عمداً از `DisabledOtpDelivery` استفاده می‌کند و هیچ کد ورود ساختگی ارسال یا تأیید نمی‌شود.

- `IPPANEL_API_KEY`: کلید API پنل پیامکی
- `IPPANEL_OTP_PATTERN_CODE`: شناسه الگوی تأییدشده در پنل IPPanel
- `IPPANEL_FROM_NUMBER`: شماره خط خدماتی/ارسال مجاز که IPPanel برای API ارائه کرده است

## تنظیم الگوی پیامک

در پنل IPPanel یک الگوی خدماتی برای رمز یک‌بارمصرف بسازید و پس از تأیید پنل، شناسه الگو را در `IPPANEL_OTP_PATTERN_CODE` قرار دهید. نام پارامتر الگو باید دقیقاً `code` باشد؛ متن پیام باید کد ارسال‌شده از سامانه را با همین پارامتر نمایش دهد. قالب و متن پیام را مطابق الزامات پنل و مقررات ارسال پیامک تنظیم کنید.

## محل نگهداری امن مقادیر

مقادیر واقعی را فقط در فایل محیطی امن سرور یا Secret Manager هاست تنظیم کنید. کلید API را در مخزن Git، فایل `.env.example`، اپلیکیشن Flutter، Repository Variables یا گفت‌وگو قرار ندهید.

نمونه نام متغیرها (مقادیر عمداً خالی هستند):

```dotenv
IPPANEL_API_KEY=
IPPANEL_OTP_PATTERN_CODE=
IPPANEL_FROM_NUMBER=
```

پس از تنظیم، کش تنظیمات Laravel را در زمان استقرار به‌روزرسانی کنید. سپس با یک شماره تحت کنترل خودتان مسیر کامل زیر را آزمایش کنید:

1. `POST /api/v1/auth/otp/request` با شماره موبایل معتبر.
2. دریافت واقعی پیامک و بررسی اینکه کد در کمتر از پنج دقیقه قابل استفاده است.
3. `POST /api/v1/auth/otp/verify` با همان شماره و کد.
4. تأیید دریافت توکن Sanctum و ورود موفق اپلیکیشن.
5. آزمایش محدودیت ارسال مجدد، انقضا و حداکثر تلاش ناموفق.

پاسخ موفق endpoint درخواست OTP به‌تنهایی کافی نیست؛ ارسال واقعی پیامک و ورود روی گوشی فیزیکی باید تأیید شود. در صورت نبود تنظیمات یا رد درخواست از سوی IPPanel، API باید خطای کنترل‌شده برگرداند و کاربر وارد حساب نشود.

## تست‌های موجود

تست واحد `backend/tests/Unit/IppanelOtpDeliveryTest.php` مسیر API، تبدیل شماره ایرانی به قالب بین‌المللی، پذیرش/رد الگو و رد شماره نامعتبر را با HTTP fake بررسی می‌کند. این تست جایگزین تست واقعی با اعتبارنامه و خط فعال پنل نیست.
